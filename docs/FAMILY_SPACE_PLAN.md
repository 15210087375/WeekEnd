## 1. 产品目标

| 目标 | 说明 |
|------|------|
| 菜单一致 | 同一家庭空间内 Region→Mall→Place→Dish 共享 |
| 点餐可见 | 成员点餐后，其他人在约定界面可见 |
| 心愿可见/可私密 | 默认空间内可见；可标私密仅自己可见 |
| 本地仍可用 | 不登录、不入空间：本机维护 + 文件备份分享 |
| 分模块存档 | 导出/导入可选 **全部** 或 **单模块**（菜单、心愿、点餐等），模块可独立管理 |
| 人数 | 每空间 **3～5 人**（含主账号） |
| 空间数 | 每用户 **同时仅 1 个空间** |

## 2. 已锁定决策（用户确认 + 推荐默认）

### 2.1 空间与成员

| 项 | 决策 |
|----|------|
| 同时加入的空间数 | **1**；须退出当前空间后才能加入另一空间 |
| 人数上限 | **5**（含主账号）；满员不可再邀请 |
| 角色 | 两档：**主账号** / **成员** |
| 主账号专属 | 踢人、解散空间、**转让主账号**、改空间名 |
| 成员可做 | 改共享菜单、点餐、管自己的心愿；见 §2.3 |
| 主账号退出 | **禁止直接退**；须先 **转让主账号** 给其他成员，或 **解散空间** |
| 邀请 | 空间码 / 小程序码；建议带过期与人数校验（实现期定细节） |
| 身份展示 | 昵称 + 可选备注（如「爸爸」）；列表/动态用展示名，不用 openid |

### 2.2 数据范围（进空间 vs 不进）

| 进空间（云同步） | 不进空间 |
|------------------|----------|
| Region / Mall / Place / Dish | 设备级 UI 偏好 |
| Order（点餐） | 未入空间时的纯本机数据（见加入策略） |
| Wish（心愿，含 visibility） | 云开发账号绑定信息（openid 映射表） |
| 对应图片（云存储 fileID） | |

历史记录若仅为本地浏览聚合，实现时可并入「空间数据的查询视图」，不单独搞第二套业务库。

### 2.3 权限（共享数据）

| 操作 | 规则 |
|------|------|
| 菜单（地理树 + 菜/菜谱） | 主号与成员均可增删改 |
| 点餐 | 创建者可改删；**主号可删任意点餐** |
| 心愿（非私密） | 创建者可改删；**主号可删任意非私密心愿** |
| 心愿（私密） | **仅创建者**读写删；主号也不可读内容（安全规则强制） |
| 解散 / 踢人 / 转让 | 仅主号 |

### 2.4 同步与冲突

| 项 | 决策 |
|----|------|
| 离线改菜单 | **允许**；写入本地 + 同步队列 |
| 冲突策略 | **LWW**：同一实体以较新时间为准 |
| 权威时间 | **服务端写入时间**盖 `updatedAt`（防改手机时间作弊）；本地时钟仅离线排序 |
| 删除 | **软删除**（`deletedAt` + `updatedAt` 墓碑），禁止「旧端复活已删数据」的硬删-only |
| 图 | **云存储**；库内只存引用，禁止把 base64 当云主存储 |
| 同步形态 | 增量（按 `updatedAt` / 版本）；禁止每次打开全表 dump |
| 云失败 | **降级本地**，不阻断录入；展示「待同步」状态 |

### 2.5 心愿可见性

| `visibility` | 含义 |
|--------------|------|
| `space`（默认） | 空间内全员可见 |
| `private` | 仅 `createdBy`；服务端鉴权，不只靠前端隐藏 |

仅本地模式：数据本就只在本机，字段可存默认 `space`，无协作语义。

### 2.6 双模式与加入 / 退出

| 模式 | 说明 |
|------|------|
| **仅本机** | 默认；LocalStore 为唯一源；文件导入导出可用 |
| **家庭空间** | 已加入唯一空间；LocalStore 为缓存 + 离线队列；云为协作源 |

**加入空间（首期交互，不做静默自动合并）**

1. 创建空空间 → 可选 **用本机数据初始化空间**  
2. 加入已有空间 → **拉云覆盖本机工作副本**（需二次确认文案）  
3. 取消  

不做首期：三路智能合并。

**退出空间**

- 本机保留退出前缓存，变为 **可继续编辑的仅本机分叉**  
- **不再写回**原空间  
- 云上空间数据仍属空间与其余成员  

**解散空间（主号）**

- 云侧空间标记解散/删除策略实现期定（建议：成员均回到仅本机，各自保留最后缓存分叉）  
- 须强确认  

### 2.7 备份与导入（含分模块存档）

#### 2.7.1 模块划分

存档按 **业务模块** 选择，互不强制捆绑：

| 模块 id | 名称 | 包含数据 | 依赖说明 |
|---------|------|----------|----------|
| `menu` | 菜单 | Region、Mall、Place、Dish + 菜品图 | 自洽；点餐里的菜名快照不依赖本模块完整树 |
| `orders` | 点餐 | Order 列表 | 可独立导出；导入不强制带菜单 |
| `wishes` | 心愿单 | Wish + 心愿图 | 完全独立 |
| `all` | 全部 | 上述全部 | 等价于勾选全部模块 |

后续新业务线（影院等）以同样方式加模块 id，备份 UI 多一组勾选。

#### 2.7.2 导出

| 项 | 决策 |
|----|------|
| 选择方式 | 用户可勾选 **一个或多个模块**，或一键 **全部** |
| 文件 | 仍为 JSON 文件（分享/打开）；文件名可带模块后缀，如 `wfa-backup-menu-…json` |
| 包内元数据 | 必须写明 `modules: string[]`（实际包含的模块列表） |
| 图片 | 仅打包 **所选模块** 相关图片（`menu`→菜品图，`wishes`→心愿图） |
| 仅本机 / 已入空间 | 均支持按模块从 **当前工作副本** 导出 |

#### 2.7.3 导入

| 项 | 决策 |
|----|------|
| 识别 | 读包内 `modules`；旧包无该字段 → 视为 `all`（兼容现网全量包） |
| 范围 | **只替换包内声明的模块**；未包含的模块 **本机数据保持不动** |
| 确认文案 | 须写清将替换哪些模块（如「仅替换心愿单，菜单与点餐不变」） |
| `menu` 导入 | 替换 regions/malls/places/dishes 及对应本地图；软策略与现网全量菜单一致 |
| `orders` 导入 | 仅替换 orders |
| `wishes` 导入 | 仅替换 wishes 及对应图 |
| 多模块同包 | 一次导入按包内模块集合分别替换 |
| 仅本机 | 按模块写入 LocalStore |
| 已入空间 | **文件导入默认只影响本机工作副本**，不自动冲云；提示与 §2.7.4 一致。整空间按模块恢复云端 → 二期且宜限主号 |

#### 2.7.4 与云 / 全量覆盖

| 场景 | 决策 |
|------|------|
| 仅本机 | 按模块导出/导入；选「全部」= 现网「全量替换」语义 |
| 已入空间 | 备份可作快照；**导入默认不得普通成员一键冲云** |
| 整空间覆盖（含按模块冲云） | **仅主号** + 二次确认；**首期可不做**，只做本机按模块导入 |

首期实现优先：

1. 导出：模块多选 + `modules` 元数据 + 按模块收图  
2. 导入：按 `modules` 局部替换 + 旧包当 `all`  
3. 已入空间：导入只动本机，文案标明  

#### 2.7.5 与「单独管理」的关系

- **运行时**：各模块本就可独立 CRUD（菜单页 / 心愿页 / 点餐页）。  
- **存档时**：再提供 **独立备份与恢复**，避免「只想备份心愿却被迫覆盖菜单」。  
- **云同步**（若已入空间）：仍按实体增量同步；分模块存档是 **文件通道** 的能力，不替代云同步。

### 2.8 点餐「互相看见」

| 项 | 决策 |
|----|------|
| 形态 | **点餐记录列表混排** + 作者展示名；可选二级「动态」后期再做 |
| 未读红点 | 首期不做；二期再加 `readAt` |
| 分享码/快照 | 现有本地分享能力保留；与空间列表并存 |

### 2.9 技术选型

| 项 | 决策 |
|----|------|
| 云 | **微信云开发**（库 + 云存储 + 云函数 + 登录） |
| 分层 | 页面 → domain → LocalStore；**CloudSync 可选插件**；页面不直接 `wx.cloud` |
| 计费 | 开发者承担；免费档试用 → 正式约基础套餐；控制用量（增量 + 缩略图） |
| 非目标 | Git/CDN 当业务库；多空间；CRDT；E2E 加密；首期订阅消息推送 |

## 3. 逻辑模型（实现指引）

### 3.1 集合 / 表（逻辑名）

| 名 | 要点 |
|----|------|
| `users` | openid → 展示名；`currentSpaceId`（空=仅本机） |
| `spaces` | id、name、ownerId、memberIds[]、createdAt、status |
| `space_members` | spaceId、userId、role(`owner`\|`member`)、nickname、joinedAt |
| 业务集合 | 现有实体字段 + `spaceId` + `createdBy` + `updatedBy` + `updatedAt`(服务端) + `deletedAt?` |
| Wish 额外 | `visibility`: `space` \| `private` |
| 图片 | 云存储路径 / fileID；实体内 `ImageRef` 扩展 cloud 字段 |

### 3.2 客户端状态机（简）

```
仅本机 ──创建/加入成功 ──► 家庭空间
家庭空间 ──退出（成员）/转让后退出/解散 ──► 仅本机（本地分叉）
```

任意状态：文件备份可用（语义见 §2.7）。

### 3.3 写入路径（家庭空间模式）

1. 校验权限（私密心愿等）  
2. 写本地缓存  
3. 入同步队列  
4. 云函数/受控写入：盖服务端 `updatedAt`，LWW 与墓碑合并  
5. 失败保留队列，UI 标待同步

## 5. 测试矩阵（上线前最低集）

1. 仅本机：CRUD、文件备份（含单模块导出/导入不伤及其他模块），无云调用  
2. 创建空间 + 本机初始化  
3. 第二人加入 + 拉云覆盖确认  
4. 离线改菜 → 上线 → 对端见到；对端同时改 → 新时间胜  
5. 软删菜 → 旧端不得复活  
6. 成员点餐 → 另一成员列表可见作者  
7. 私密心愿：另一成员与主号均不可读（规则/函数层）  
8. 满 5 人邀请失败  
9. 主号未转让不能退；转让后可退  
10. 退出后本机可编辑且不再写云  
11. 云失败时仍可本地录入
